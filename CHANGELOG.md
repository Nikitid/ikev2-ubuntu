# Журнал изменений

Заметные изменения проекта перечислены в этом файле.

## 1.4.0 — 2026-09-01

Исправления ошибок:

- Экспорт клиентских наборов не работал: меню выбора группы печаталось в
  стандартный вывод, который перехватывался подстановкой команды, поэтому
  список групп не отображался, а выбранной группой становился весь текст
  меню.
- `net.netfilter.nf_conntrack_max` не применялся после перезагрузки:
  `systemd-sysctl` выполняется до загрузки модуля `nf_conntrack`. Модуль
  добавлен в `/etc/modules-load.d`, значение проверяется после применения.
- Сгенерированные файлы не обновлялись при обновлении скрипта. Теперь они
  содержат отметку версии, а расхождение приводит к перегенерации и
  повторному применению при запуске или по команде `--reconcile`.
- В режиме `http-01` ограничение входящего трафика блокировало TCP-порт `80`
  и ломало автоматическое продление сертификата.
- Ссылка MTProto после добавления пользователя показывала секрет первого
  пользователя. Секреты читаются по имени учетной записи, меню показывает
  ссылку для каждого пользователя.
- Группа с дефисом в имени не выбиралась при экспорте: явное поле группы
  обрезалось по первому дефису.
- Ловушка `ERR` не срабатывала внутри функций, поэтому строка «Last error»
  всегда была пустой.
- Разбор `config.toml` прокси больше не может принять `mask_port` за порт
  сервера.

Безопасность:

- Добавлена политика исходящего трафика `internet-only` (по умолчанию):
  клиентам закрыты метаданные облака `169.254.0.0/16`, частные сети и службы
  самого сервера. Нужные клиентам порты хоста перечисляются отдельно,
  прежнее поведение доступно как `open`.
- Пароли VPN и токены DNS-провайдера вводятся без отображения на экране.
- Клиентские наборы создаются с `umask 077`, а не исправляются после записи.
- `acme.sh` устанавливается с закрепленного тега; неподкрепленный установщик и
  bootstrap MTProto выполняются только после подтверждения отпечатка sha256.
- Резервные копии сертификатов и ключей ротируются.

Изменения поведения:

- Поддержана Ubuntu 26.04 LTS; список поддерживаемых выпусков вынесен в одно
  место.
- Скрипт больше не сохраняет живой набор правил в `/etc/iptables`: туда
  попадали правила Docker, ufw и провайдера. Правила восстанавливает
  собственный unit при загрузке.
- Удаление больше не отключает `net.ipv4.ip_forward`, если он нужен другой
  службе, не удаляет чужие файлы в `/etc/swanctl/conf.d`, не выполняет
  `apt-get autoremove` и предлагает удалить только те пакеты, которые
  установил сам.
- Пункт очистки доступен и в меню «не установлено», если на диске остались
  файлы менеджера.
- Нумерация пунктов меню больше не зависит от состояния службы; удаление
  вынесено на отдельную клавишу.
- Тип ключа сертификата настраивается (`rsa2048` по умолчанию, доступны
  `ec256`/`ec384`), политика `unique` вынесена в конфигурацию.
- `childless = allow` добавляется, если strongSwan не ниже 5.9.6.
- Добавлены команды `--check`, `--reconcile`, `--diagnostics`, `--version`,
  `--help` и проверка наличия терминала.
- Добавлены просмотр активных сессий VPN, счетчик неудачных аутентификаций
  EAP и ежедневный таймер проверки срока действия сертификата.
- Порты SSH определяются при генерации правил, а не при загрузке; в список
  разрешенных добавлен DHCPv4.
- Скрипт для Ubuntu-клиента сохраняет существующие `ipsec.conf` и
  `ipsec.secrets` и поставляет корневой сертификат вместо промежуточного.
- Правила IPv6 приводятся к выбранному режиму: переключение
  `block`/`nat`/`off` удаляет правила прежнего режима.
- Предупреждение о пересечении пула VPN с сетями, уже настроенными на хосте.

## 1.3.2 — 2026-07-27

- Исправлена роль сертификатов цепочки ACME в strongSwan: промежуточные
  сертификаты загружаются из `x509` и отправляются клиенту, а системный
  корневой сертификат загружается как trust anchor из `x509ca`.
- Файлы резервных копий перенесены из каталогов credentials в
  `/opt/ikev2-manager/backups`, чтобы strongSwan не загружал устаревшие
  сертификаты и ключи.

## 1.3.1 — 2026-07-27

- Проект и публичный репозиторий переименованы в `ikev2-ubuntu`.
- Удалена интеграция с 3x-ui.
- Выбор режима ACME заменён на меню DNS-01/HTTP-01.
- Цепочка CA от `acme.sh` разделяется на отдельные PEM-файлы для strongSwan.
  Это обеспечивает загрузку всех промежуточных сертификатов, включая новые
  цепочки Let’s Encrypt Generation Y, и сохраняется при автоматическом
  продлении сертификата.
- Минимальный лимит таблицы conntrack для VPN/NAT увеличен до 32768 без
  понижения более высокого значения администратора. В диагностику добавлено
  текущее заполнение таблицы и предупреждения при высокой загрузке.

## 1.3.0 — 2026-06-25

- MTProxy (C, сборка из исходников) заменён на
  [mtproto.zig](https://github.com/sleep3r/mtproto.zig) (Zig, предсобранный
  бинарник) Александра Калашникова (sleep3r), лицензия MIT. Новый прокси
  использует FakeTLS 1.3, анти-повтор и активное зондирование-маскировку.
  TLS-домен задаётся при установке и не меняется; для смены требуется
  переустановка. Устаревший C-MTProxy и его правила iptables очищаются
  автоматически при первой установке нового прокси.
- Исправлен парсинг секрета MTProto из `config.toml`: awk-выражение в
  `mt_load_config` некорректно обрезало открывающую кавычку, что приводило
  к генерации неверной ссылки `tg://` и невозможности подключиться.
- Документация приведена к единой русско-английской структуре.
- Добавлен файл `THIRD_PARTY_LICENSES.md` с уведомлением об авторских правах
  mtproto.zig согласно требованиям MIT.
