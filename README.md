# ikev2-ubuntu

[English](README.en.md)

[![Лицензия: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)
[![Проверки](https://github.com/Nikitid/ikev2-ubuntu/actions/workflows/check.yml/badge.svg)](https://github.com/Nikitid/ikev2-ubuntu/actions/workflows/check.yml)

Интерактивный Bash-скрипт для установки и обслуживания IKEv2/IPsec-сервера
на Ubuntu. Проект рассчитан на один сервер и использует strongSwan с
`swanctl`, сертификаты ACME, пользователей EAP-MSCHAPv2 и правила
межсетевого экрана.

## Состояние

Поддерживаются Ubuntu 22.04, 24.04 и 26.04 LTS. Актуальная стабильная
версия — `v1.5.0`.

## Возможности

- установка, переустановка и удаление IKEv2-сервера;
- выпуск сертификатов через `acme.sh` с проверкой `dns-01` или `http-01`;
- управление VPN-пользователями и экспорт клиентских конфигураций;
- IPv4 full tunnel, защита от утечек IPv6 или NAT66;
- изоляция VPN-клиентов и ограничение входящего трафика;
- политика исходящего трафика: клиенты не видят метаданные облака, частные
  сети и службы самого сервера;
- диагностика, журналы, активные сессии, управление службами и обновление
  сертификатов;
- ежедневная проверка срока действия сертификата с записью в журнал;
- дополнительное управление MTProto-прокси ([telemt](https://github.com/telemt/telemt),
  TELEMT Public License).

## Требования

- Ubuntu 22.04, 24.04 или 26.04 LTS;
- права `root`;
- systemd и iptables;
- публичное доменное имя, указывающее на сервер.

## Установка

Стабильный релиз:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/Nikitid/ikev2-ubuntu/v1.5.0/scripts/ikev2-manager.sh)
```

Текущая ветка `main`:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/Nikitid/ikev2-ubuntu/main/scripts/ikev2-manager.sh)
```

Перед запуском удаленного скрипта рекомендуется проверить его содержимое и
использовать закрепленный тег релиза.

## Использование и конфигурация

Скрипт открывает интерактивное меню. Управляемые файлы и состояние хранятся в
`/opt/ikev2-manager`.

- UDP-порты `500` и `4500` должны быть открыты во внешнем межсетевом экране.
- Для `http-01` входящий TCP-порт `80` нужен и при выпуске сертификата, и при
  каждом автоматическом продлении; ограничение входящего трафика оставляет
  этот порт открытым в данном режиме.
- Для `dns-01` потребуются учетные данные выбранного DNS-провайдера.
- Пароли VPN и экспортированные клиентские наборы содержат секреты.

### Неинтерактивные команды

```bash
ikev2-manager.sh --check        # отчет о состоянии, ненулевой код при проблеме
ikev2-manager.sh --reconcile    # перегенерация файлов и повторное применение
ikev2-manager.sh --diagnostics  # полный отчет диагностики
ikev2-manager.sh --version
```

`--check` подходит для мониторинга: команда завершается с ошибкой, если служба
не запущена, до истечения сертификата меньше 21 дня, отсутствуют правила
межсетевого экрана или сгенерированные файлы устарели.

### Политика исходящего трафика

`internet-only` (по умолчанию) отбрасывает трафик из пула клиентов к
метаданным облака (`169.254.0.0/16`), в частные сети и к службам самого
сервера; указанные DNS-серверы клиентов остаются доступны. Службы самого
сервера, которые нужны клиентам (SSH через туннель, MTProto-прокси),
перечисляются отдельным списком портов. `open` возвращает прежнее поведение
с маршрутизацией всего трафика. Режим меняется в «Service menu -> Inbound
hardening / client isolation / egress policy».

### Обновление версии

Сгенерированные файлы содержат отметку версии, которая их создала. При первом
запуске после обновления менеджер перегенерирует скрипт межсетевого экрана,
параметры sysctl и вспомогательные скрипты сертификата и применяет их заново,
поэтому настройка, сделанная в старой версии, не остается неприменённой. То же
самое выполняет `--reconcile`.

### Ошибка Windows 13801 после обновления сертификата

Новые цепочки Let’s Encrypt могут содержать несколько промежуточных
сертификатов. Менеджер загружает их как недоверенные промежуточные сертификаты,
а системный корень — как trust anchor. Это заставляет strongSwan отправлять
полную цепочку в IKE_AUTH. После обновления старой установки повторно выпустите
сертификат через сервисное меню и проверьте `Loaded CA chain files` в
диагностике.

## Разработка

```bash
bash -n scripts/ikev2-manager.sh
shellcheck scripts/ikev2-manager.sh tests/run-tests.sh
shfmt -i 2 -bn -ci -d scripts/ikev2-manager.sh tests/run-tests.sh
bash tests/run-tests.sh
```

Дополнительные правила работы с репозиторием описаны в [AGENTS.md](AGENTS.md).

## Безопасность

Не публикуйте конфигурацию из `/opt/ikev2-manager`, пароли, сертификаты,
закрытые ключи и клиентские наборы. Об уязвимости сообщайте приватным
security advisory на GitHub.
